1. หลักการและฐานทางกฎหมาย Purpose & legal basis

ผู้ประกอบการจดทะเบียนภาษีมูลค่าเพิ่มที่ประกอบกิจการค้าปลีก สามารถออก ใบกำกับภาษีอย่างย่อ ผ่าน เครื่องบันทึกการเก็บเงิน (POS) ได้ ต่อเมื่อได้รับ อนุมัติจากอธิบดีกรมสรรพากร ก่อน โดยยื่นแบบ ภ.พ.06 ต่อสำนักงานสรรพากรพื้นที่ ที่สถานประกอบการตั้งอยู่ (มาตรา 86/6 แห่งประมวลรัษฎากร)

ข้อควรระวัง: ห้ามออกใบกำกับภาษีอย่างย่อจากเครื่องก่อนได้รับอนุมัติ เนื่องจากลำดับเลขที่เอกสาร ต้องสอดคล้องกับวันที่ได้รับอนุมัติ ระยะเวลาพิจารณาโดยทั่วไปประมาณ 30–45 วันทำการ
Do not issue abbreviated tax invoices from the machine before approval — the document-number sequence must align with the approval date. Review typically takes 30–45 business days.

อ้างอิง: กรมสรรพากร — หลักเกณฑ์การใช้เครื่องบันทึกการเก็บเงิน (rd.go.th/44309.html), แบบ ภ.พ.06 (rd.go.th), ประมวลรัษฎากร มาตรา 86/6.

4. คุณสมบัติของระบบ (เทียบมาตรา 86/6) Software capability vs. required invoice fields

ใบกำกับภาษีอย่างย่อต้องมีรายการครบตามมาตรา 86/6 ตารางด้านล่างแสดงสถานะจริงในระบบ BravePOS

รายการที่กฎหมายกำหนด / Required itemการรองรับใน BravePOSสถานะ
คำว่า "ใบกำกับภาษีอย่างย่อ"พิมพ์บนหัวใบเสร็จ "ใบเสร็จรับเงิน/ใบกำกับภาษีอย่างย่อ"มีอยู่แล้ว
ชื่อ / ชื่อย่อ ผู้ประกอบการชื่อบริษัท + สาขา จากการตั้งค่ามีอยู่แล้ว
เลขประจำตัวผู้เสียภาษีของผู้ขาย (TIN)"เลขประจำตัวผู้เสียภาษี" บนใบเสร็จมีอยู่แล้ว
หมายเลขเครื่อง POS ที่ได้รับอนุมัติพิมพ์ "POS ID / POS #" — ต้องผูกกับเลขเครื่องที่สรรพากรออกให้ปรับให้ผูกเลขอนุมัติ
เลขที่/ลำดับของเอกสาร (running no.)เลขที่ใบเสร็จ PS + 9 หลัก เรียงลำดับ ไม่ซ้ำปัจจุบัน global — ควรแยกรายเครื่อง
วัน เดือน ปี ที่ออกใบกำกับภาษีพิมพ์วันที่/เวลา (รองรับปี พ.ศ. ในเวอร์ชันเว็บ)มีอยู่แล้ว
ชื่อ ชนิด ประเภท ปริมาณ ของสินค้า/บริการรายการสินค้า จำนวน ราคา (snapshot กันแก้ย้อนหลัง)มีอยู่แล้ว
ราคาสินค้า ที่รวมภาษีมูลค่าเพิ่มแล้วยอดรวม + ข้อความ "ราคาสินค้ารวมภาษีมูลค่าเพิ่มแล้ว"มีอยู่แล้ว
แยกแสดงมูลค่าก่อน VAT และจำนวน VAT 7%บรรทัด "มูลค่าสินค้าก่อน Vat" และ "ภาษี 7%" (VAT-inclusive: goods×7/107)มีอยู่แล้ว
การคำนวณ VAT ใช้ฐานราคารวมภาษี (inclusive): vat = ยอดสินค้า × 7 / 107 อัตราปรับได้จากการตั้งค่าร้าน (ค่าเริ่มต้น 7%).

6. ข้อกำหนดด้านความปลอดภัยและความถูกต้องของข้อมูล Security & data-integrity specification

ส่วนนี้คือหัวใจของมาตรฐาน POS ของสรรพากร — ข้อมูลการขายต้องบันทึกครบถ้วน แก้ไข/ลบไม่ได้ และตรวจสอบย้อนหลังได้ ตารางแสดงมาตรการควบคุมพร้อม สถานะจริง ของระบบ

มาตรการควบคุม / Controlรายละเอียดสถานะ
การบันทึกการขายเป็นศูนย์กลางเดียวทุกการขายผ่านฟังก์ชันเดียว (atomic transaction + row lock) กันเลขซ้ำ/แข่งกันบันทึกมีอยู่แล้ว
เลขที่เอกสารเรียงลำดับ ไม่ซ้ำเลข PS+9 หลัก unique constraint + retry — ควรแยกลำดับ "รายเครื่องที่อนุมัติ"บางส่วน
Snapshot รายการสินค้าชื่อ/ราคา/หมวดหมู่ ถูกคัดลอกลงบิล การแก้ไขสินค้าภายหลังไม่กระทบบิลเดิมมีอยู่แล้ว
บันทึกแก้ไข/ลบไม่ได้ (Immutable / append-only)เมื่อออกบิลแล้วต้องแก้ไข/ลบไม่ได้; ต้องมี updated_at และห้าม overwriteต้องพัฒนา
การยกเลิกบิล (Void) เก็บถาวรVoid ต้องเป็นรายการกลับบัญชีที่ เก็บบิลเดิมไว้ พร้อมผู้ทำ/เวลา — ปัจจุบัน stamp ลบได้เมื่อ un-cancelต้องแก้
ตัวนับยอดขายสะสม (Grand Total / GT)ตัวนับยอดขายสะสมที่เพิ่มขึ้นอย่างเดียว รีเซ็ตไม่ได้ พิมพ์บนรายงาน Z ทุกครั้งยังไม่มี
รายงานปิดยอดประจำวัน (Z) เก็บถาวร + เลขลำดับ Zปัจจุบัน "สรุปปิดรอบ" คำนวณสด ไม่เก็บ snapshot ไม่มีเลข Z และไม่มียอด VATต้องพัฒนา
ป้องกันตัวตน/ลายเซ็นข้อมูล (tamper-evidence)ควรมี hash ต่อบิลผูกกับบิลก่อนหน้า (hash chain) เพื่อจับการแก้ไขเงียบยังไม่มี
ปิดช่องลบข้อมูลทั้งหมดendpoint seed_data ที่ลบออเดอร์ทั้งหมด ต้องปิด/ถอดออกในเครื่องที่อนุมัติแล้วต้องถอด
ควบคุมสิทธิ์การเข้าถึง (Access control)ล็อกอินระดับ backoffice + PIN พนักงานรายสาขา (Admin/Cashier); จำกัดสิทธิ์ void/refundบางส่วน
สำรอง/ซิงค์ข้อมูลขึ้นคลาวด์บันทึกขึ้น Backend ทันที; ข้อมูลไม่อยู่บนเครื่องอย่างเดียวมีอยู่แล้ว
บันทึกร่องรอยการใช้งาน (Audit log)มี created_at ทั่วระบบ, log การเรียก API ภายนอก; ยังไม่มี audit log ระดับบิลครบถ้วนบางส่วน
สรุปช่องว่างสำคัญ (blockers): ตัวนับยอดสะสม GT · รายงาน Z แบบเก็บถาวรมีเลขลำดับและ VAT · บิลแก้ไข/ลบไม่ได้และ void เก็บถาวร · ถอด endpoint ลบข้อมูล · แยกลำดับเลขที่รายเครื่องอนุมัติ. รายการเหล่านี้ต้องพัฒนาให้เสร็จก่อนยื่นจริง.

Cถอด/ล็อก endpoint ลบข้อมูล (seed_data) ในเครื่องที่อนุมัติสูงต้องแก้
Dผูกเลขเครื่อง POS + ลำดับเลขที่ใบเสร็จ กับเลขที่สรรพากรอนุมัติ (รายเครื่อง)สูงปรับ
Eทะเบียนรายงานภาษีขาย (VAT output) + ส่งออกสำหรับยื่นกลางปรับ
Fจำกัดสิทธิ์ void/refund + audit log ระดับบิลกลางบางส่วน
Gรวบรวมสเปกเครื่อง + วาดผังติดตั้ง/เครือข่ายจริง + กรอก ภ.พ.06งานเอกสารรวบรวม
ลำดับแนะนำ: ทำ A–C (fiscal integrity) ให้เสร็จก่อน เพราะเป็นเงื่อนไขที่สรรพากรตรวจจริง จากนั้น D–F แล้วจึงจัดชุดเอกสาร G เพื่อยื่น ภ.พ.06.
