Two jobs, one screen: a branch that has just opened needs a menu, promotions and dropdowns, and something added at one shop needs to reach the others. Both are "make that branch's lists look like this one". What travels is ticked per section — see bravepos/branch_sync.py, where each section lives; a new list is one entry there and shows up here unchanged. Every section adds what the target is missing and edits what it has to match. Rows only the target has are left alone, and stock is never copied. Two forms, not one. Choosing branches and sections is a GET that only previews; the sync is a separate POST carrying the same choices as hidden fields. So the write can only be reached from a preview that is on screen — with the two folded into one form, a browser with JS off would submit straight to the sync and skip the preview entirely. The preview names the rows rather than counting them.
