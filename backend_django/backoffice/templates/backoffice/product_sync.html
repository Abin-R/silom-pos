{% extends "backoffice/base.html" %} {% comment %} Screen — Sync products between branches. Two jobs, one screen: a branch that has just opened needs a menu, and a product added at one shop needs to reach the others. Both are "make that branch's list look like this one". The page only ever *adds*. A product the target already has keeps its own price, cost, photo and stock. That is said three times on purpose — in the banner, in the preview column, and beside the button — because the one thing an admin must be sure of before pressing this on a live branch is that it cannot rewrite the prices that branch is trading on. Two forms, not one. Choosing branches is a GET that only previews; the copy is a separate POST carrying the same choices as hidden fields. So the write can only be reached from a preview that is on screen — with the two folded into one form, a browser with JS off would submit straight to the copy and skip the preview entirely. The preview names the products rather than counting them. "18 will be added" is not something anybody can check, and this page writes to branches nobody is looking at. {% endcomment %} {% block title %}Sync products{% endblock %} {% block page_title %}Sync products{% endblock %} {% block page_sub %}
