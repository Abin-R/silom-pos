{% extends "backoffice/base.html" %} {% comment %} Screen — Sync products between branches. Two jobs, one screen: a branch that has just opened needs a menu, and a product added at one shop needs to reach the others. Both are "make that branch's list look like this one". It adds, edits and removes: every product the source sells is added where missing or edited to match where present (found by Shopster ID, then name), and what the source removed is taken off sale. Products only the target sells are left alone; stock, par level and counter minimum are never touched. Because it now rewrites prices at branches nobody is looking at, the preview lists every edit with its before → after. Two forms, not one. Choosing branches is a GET that only previews; the copy is a separate POST carrying the same choices as hidden fields. So the write can only be reached from a preview that is on screen — with the two folded into one form, a browser with JS off would submit straight to the copy and skip the preview entirely. The preview names the products rather than counting them. "18 will be added" is not something anybody can check, and this page writes to branches nobody is looking at. {% endcomment %} {% block title %}Sync products{% endblock %} {% block page_title %}Sync products{% endblock %} {% block page_sub %}
